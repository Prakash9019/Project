Context

Decisions confirmed by the user:
- Messaging = hybrid "Message Requests" inbox. A first DM from a stranger opens a conversation
in pending state that shows in the receiver's Requests folder. Replying/accepting → active;
the receiver can dismiss or block. This replaces the hard accept/ignore intro-request gate.
- External services = contracts + stubbed adapters. Full DB models, REST endpoints, and WebRTC
call signaling are built; SMS, payments, AI verification, translation, and moderation live behind
adapter interfaces with clearly-marked stub implementations (no provider keys needed to run).
- Premium = exposed, not enforced. Premium features are fully implemented; a premium helper
marks/gates them but passes through in dev (TODO to enforce by tier). Spec marks them premium.
